# Платформа пользовательского контента «12 шагов»

## Цель

Расширить Telegram Mini App Unity One до приложения «12 шагов», в котором посетители читают материалы, посты, инструменты и личный опыт, а авторизованные через Telegram пользователи создают собственные публикации и отправляют их на модерацию.

## Основные решения

- Публичное название приложения: «12 шагов».
- Под заголовком на главной странице размещается текст: «материалы · посты · полезные инструменты · опыт · и прочее».
- Публикации хранятся в единой коллекции Appwrite `publications` и различаются полем `type`.
- Читать опубликованные записи могут все посетители.
- Создавать публикации и управлять ими могут только пользователи с валидным Telegram `initData`.
- Все публикации проходят модерацию.
- Модерация выполняется внутри приложения администраторами, чьи Telegram ID перечислены в `ADMIN_TELEGRAM_IDS`.
- Изображения в пользовательские публикации не добавляются.

## Типы публикаций

Приложение поддерживает четыре независимых типа:

- `material` — материалы;
- `post` — посты;
- `tool` — полезные инструменты;
- `experience` — личный опыт.

Категория и теги доступны только постам. Инструменты не имеют категорий и тегов. Материалы и опыт также не используют категории и теги на первом этапе.

## Маршруты

- `/app/` — главная страница.
- `/app/materials/` — каталог материалов.
- `/app/materials/[id]/` — материал.
- `/app/posts/` — каталог постов с динамическими категориями и тегами.
- `/app/posts/[id]/` — пост.
- `/app/tools/` — каталог инструментов.
- `/app/tools/[id]/` — инструмент.
- `/app/experience/` — каталог личного опыта.
- `/app/experience/[id]/` — публикация с опытом.
- `/app/create/` — выбор типа новой публикации.
- `/app/create/[type]/` — создание публикации и редактирование черновика.
- `/app/profile/` — профиль текущего пользователя и его публикации.
- `/app/admin/` — очередь модерации.

Публичные страницы деталей используют стабильный Appwrite document ID. Человекочитаемые slug-маршруты не вводятся на первом этапе, чтобы избежать отдельной логики уникальности и переименований.

## Нижняя навигация

Нижняя панель фиксируется над `safe-area-inset-bottom` и содержит пять пунктов:

1. Главная.
2. Материалы.
3. Создать.
4. Посты.
5. Профиль.

Кнопки круглые, визуально похожи на radio input. Активный пункт заметно выделяется. Каждый пункт имеет иконку, текстовую подпись и доступное имя. «Инструменты» и «Опыт» доступны через главную страницу и экран создания.

## Telegram-профиль

Профиль показывает:

- фотографию Telegram;
- имя и username, если он есть;
- дату первой регистрации;
- дату последней успешной авторизации;
- все публикации пользователя, сгруппированные по типу и статусу.

Профиль создаётся или обновляется только после серверной проверки Telegram `initData`. Значение `telegramId`, присланное обычным полем формы, не считается доверенным.

## Редактор

Контент хранится как ограниченный Markdown. Панель редактора поддерживает только:

- заголовок второго уровня;
- заголовок третьего уровня;
- жирный текст;
- курсив;
- ссылку;
- маркированный список;
- нумерованный список.

Произвольный HTML, изображения, код, таблицы и другие конструкции запрещены. На сервере Markdown повторно валидируется и очищается. Ссылки допускают только безопасные протоколы `https`, `http` и `mailto`.

Форма публикации содержит заголовок, краткое описание и редактор. Для поста дополнительно доступны одна категория и список тегов. Для инструмента, материала и опыта поля категории и тегов отсутствуют.

## Жизненный цикл публикации

Статусы:

- `draft` — редактируемый автором черновик;
- `review` — отправлено на модерацию и заблокировано для автора;
- `published` — опубликовано;
- `rejected` — возвращено автору на доработку с комментарием модератора.

Допустимые переходы:

- автор: новый документ → `draft`;
- автор: `draft` или `rejected` → `review`;
- администратор: `review` → `published`;
- администратор: `review` → `rejected` с обязательным комментарием;
- автор: `rejected` → `draft` при первом изменении.

Опубликованная версия не редактируется напрямую на первом этапе. Если автору потребуется внести изменения, администратор возвращает запись в `rejected`, после чего она временно исчезает из публичного каталога и проходит повторную модерацию.

## Коллекция Appwrite `publications`

Минимальные поля:

- `type`: string;
- `status`: string;
- `title`: string;
- `summary`: string;
- `content`: string;
- `category`: string, пустая строка для типов кроме `post`;
- `tags`: string array, пустой массив для типов кроме `post`;
- `authorTelegramId`: string;
- `authorName`: string;
- `authorUsername`: string;
- `authorPhotoUrl`: string;
- `moderationNote`: string;
- `createdAt`: string;
- `updatedAt`: string;
- `submittedAt`: string;
- `publishedAt`: string.

Индексируются сочетания `type + status + publishedAt`, `authorTelegramId + updatedAt`, а для постов — `category` и `tags` в пределах возможностей Appwrite.

К существующей коллекции Telegram-профилей добавляются или подтверждаются поля `createdAt` и `updatedAt`: первое хранит первую регистрацию, второе — последнюю успешную авторизацию.

## Публичные каталоги

Сервер запрашивает из Appwrite только записи со статусом `published` и нужным `type`. Каталоги сортируются по `publishedAt` от новых к старым.

На странице постов категории и теги вычисляются из текущего набора опубликованных постов. Пустые значения не показываются. Фильтр по категории и тегу не раскрывает черновики или записи на модерации.

## API и авторизация

Предлагаемые серверные маршруты:

- `GET /api/publications` — публичный список опубликованных записей с фильтрами.
- `GET /api/publications/[id]` — опубликованная запись или собственная запись авторизованного пользователя.
- `POST /api/publications` — создать черновик.
- `PATCH /api/publications/[id]` — изменить собственный `draft` или `rejected`.
- `POST /api/publications/[id]/submit` — отправить на модерацию.
- `GET /api/profile/publications` — публикации текущего пользователя.
- `GET /api/admin/publications` — очередь модерации.
- `POST /api/admin/publications/[id]/publish` — публикация.
- `POST /api/admin/publications/[id]/reject` — возврат на доработку.

Каждый непубличный запрос:

1. получает Telegram `initData`;
2. проверяет подпись, срок действия и обязательные поля;
3. извлекает Telegram ID только из проверенных данных;
4. проверяет право собственности или присутствие ID в `ADMIN_TELEGRAM_IDS`;
5. валидирует переход статуса и входные данные;
6. выполняет минимально необходимую операцию Appwrite.

`ADMIN_TELEGRAM_IDS` хранит список числовых ID через запятую. Отсутствующая или пустая переменная не предоставляет права администратора никому.

## Валидация и защита

- Заголовок, описание, контент, категория и теги имеют серверные ограничения длины.
- Пустой или состоящий из одной разметки контент не принимается.
- HTML и неподдерживаемые Markdown-конструкции отклоняются с ошибкой валидации.
- Опасные URL-схемы запрещаются.
- Клиент не может назначить автора, статус, даты публикации или модератора.
- Повторная отправка одного и того же перехода статуса идемпотентна и не создаёт новую запись.
- Appwrite API key остаётся только на сервере.
- Публичные ответы не содержат Telegram ID автора.

## Ошибки и сохранность текста

Редактор сохраняет незавершённый ввод в `sessionStorage`, отдельно для типа публикации и редактируемого ID. После успешного сохранения серверного черновика локальная копия удаляется.

Форма различает ошибки авторизации, валидации, конфликта статуса и временную ошибку сервера. При любой ошибке введённый текст остаётся в редакторе. Повторная отправка блокируется, пока предыдущий запрос выполняется.

## Модерация

Страница администратора показывает записи `review` от старых к новым. Карточка содержит тип, автора, дату отправки, заголовок, описание и полностью отрендеренный контент.

Администратор может:

- опубликовать запись;
- вернуть запись на доработку с обязательным объяснением;
- открыть профиль автора и другие его записи.

Интерфейс скрывается от обычных пользователей, но основная защита всегда выполняется на сервере.

## Тестирование

Автоматические проверки покрывают:

- проверку Telegram `initData` и извлечение автора;
- права владельца и администратора;
- допустимые и запрещённые переходы статусов;
- правила полей для четырёх типов публикаций;
- ограниченный Markdown и безопасные ссылки;
- идемпотентную повторную отправку;
- выборку только опубликованных записей;
- динамические категории и теги постов;
- отсутствие приватного Telegram ID в публичных ответах.

Лёгкая проверка Astro должна проходить без ошибок. Браузерная проверка охватывает главную страницу, нижнюю навигацию на мобильном экране, создание черновика, отправку на модерацию, решение администратора и появление записи в публичном каталоге и профиле.

## Вне первого этапа

- загрузка изображений и файлов;
- комментарии и реакции;
- подписки на авторов;
- публичные профили авторов;
- история версий опубликованной записи;
- человекочитаемые slug;
- уведомления автору через Telegram-бота;
- полноценная административная аналитика.
